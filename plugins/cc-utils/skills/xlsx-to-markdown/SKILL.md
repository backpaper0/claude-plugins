# xlsx-to-markdown

1シートに見出し番号・本文・表・図（Excelの描画オブジェクトや画像）が詰め込まれた「シート内文書」形式のxlsxを、`unzip`とPythonでXMLを直接パースして内容を読み取り、忠実なMarkdownドキュメントへ変換するスキル。openpyxl等のライブラリが使えない環境（インターネット非接続、pip不可など）でも動作する。

対象は主に方式設計書・仕様書のような「Excelを紙の代わりに使ったドキュメント」。通常の集計表・台帳のようなデータ用途のxlsxには使わない。

## 前提

- `unzip`と`python3`（標準ライブラリのみ）が使えること
- 本スキルの `scripts/inspect_xlsx.py` を使う。事前にビルドや依存インストールは不要

## 手順

### 1. 対象ファイルの確認

変換対象のxlsxパスをユーザーに確認する（複数ある場合はすべて列挙してもらう）。出力先も特に指定がなければ「元のxlsxと同じディレクトリに、拡張子を`.md`に変えたファイル名」をデフォルトとする。

### 2. 展開とシート構成の把握

作業用ディレクトリ（スクラッチパスなど）にxlsxを展開し、シート構成を確認する。

```
unzip -q "<file>.xlsx" -d <work_dir>
python3 scripts/inspect_xlsx.py <work_dir> sheets
```

出力される `state=visible` / `state=hidden` を確認する。

- 可視シートが変換対象の本文。複数の可視シートがある場合は、それぞれ独立した文書なのか、ひとつの文書の分割（表紙・改訂履歴・本文など）なのかをファイル名やシート名から判断し、不明ならユーザーに確認する
- 非表示（hidden）シートは、多くの場合ドキュメント作成時の作業用シート（下書き・別案の図・補足資料）であり、可視シートの本文からは参照されているだけのことが多い。`grid`コマンドでセル内容を覗き、実質的にテキストが無い（図形のみ）場合は変換対象から除外してよい。テキストがあり本文からも言及されている場合はユーザーに含めるか確認する

### 3. 本文テキストの読み取り

対象シートの全体像を掴むため、まずグリッド全体をダンプする。

```
python3 scripts/inspect_xlsx.py <work_dir> grid "<シート名>"
```

出力は `行番号<TAB>セル1|セル2|セル3|...` の形式（空文字のセルもそのまま`|`区切りで残るので、値が入っている列位置＝インデントの深さが視覚的にわかる）。ふりがな（`<rPh>`要素）は自動的に除外されるので、本文と読み仮名が連結されて壊れることはない。

この出力を頭から通読し、次を把握する。

- 見出し番号の階層（例: `5.` → `5.1.` → `5.1.1.` → `(1)` のような入れ子）とインデント位置（値が出現する列番号）の対応
- 本文・箇条書き・表・図（テキストが極端に少ない/空白が続く行の塊）の区間
- 表は同じ列位置に見出し行（項目名・説明など）が現れる区間として見つかる

ファイルが大きい場合はgrid出力を一度ファイルに保存し、Readツールでオフセットを変えながら読み進めるとよい。

### 4. 表の正確な構造確認

gridの`|`区切りだけでは、セルの折り返し（同じ論理セルの内容が複数の物理行に分かれている）や結合セルの範囲が読み取りづらいことがある。該当する行範囲について、セル参照とマージ情報を確認する。

```
python3 scripts/inspect_xlsx.py <work_dir> cells "<シート名>" <開始行> <終了行>
```

`r{行}c{列}: '値'` の形式でセルを列挙し、範囲にかかる結合セル(`rows x-y cols a-b`)も表示する。これを見て、以下を判断する。

- 結合されていないが同じ列位置に複数行連続している場合 → 折り返しなので、Markdown化の際は1つの論理セル（1文字列 or `<br/>`区切り）に結合する
- 実際に結合されている場合 → その通りMarkdown表のセル結合として扱う（Markdown表自体はセル結合を表現できないため、結合範囲の左上セルに内容を書き、見た目上結合されていたことが分かるようにする。厳密な再現より可読性を優先してよい）

### 5. 図（描画オブジェクト）のテキスト抽出

シートに紐づく図形・テキストボックス・画像の一覧を確認する。

```
python3 scripts/inspect_xlsx.py <work_dir> shapes "<シート名>"
```

各行は `row=<アンカー行> col=<アンカー列> name=<図形名> text=[...]` の形式（画像の場合は `[PICTURE -> xl/media/...]` も付与される）。`row`の値を、手順3で読み取った本文の行番号と突き合わせることで、「どの図がどの節に属するか」「どの説明文の直後に置かれた図か」が分かる。

`text`には図形内のテキストボックス・オートシェイプの文字列がアンカー内での出現順とは限らない順序で列挙される（Excelの図形グループ内の走査順に依存する）。図の構造（箱と矢印の関係、階層）は、文章の説明や表の内容、図形名（`Rectangle`, `四角形: 角を丸くする`, `円柱`＝データベース/テーブルの意匠, `直線矢印コネクタ`, `コネクタ: カギ線` など）から推測し、抽出した文字列だけを使って組み立てる。**抽出できていない文字列を推測で補って書き加えない。**

### 6. 図の変換方針

図の種類によって扱いを分ける。

- **`text`が取得できる図形（グループ化・四角形・テキストボックス・矢印コネクタなど）**: 内容が把握できているので、Mermaidの`flowchart`（構成図・フロー図）や`sequenceDiagram`（時系列のやり取り）として再現する。正確なピクセル位置やレイアウトの再現は不要。ラベルや矢印の向き・箱同士の関係性など、情報として意味のある部分を落とさず表現できていればよい
- **`[PICTURE -> ...]`と表示される画像**:
  - PNG/JPEG等、Readツールで直接開ける形式なら開いて内容を確認する。装飾用の小さいアイコン（時計・矢印など）であれば、それが表す意味を図の説明に反映する程度でよい。図そのものが写真・スクリーンショットとして情報を持つ場合は、その内容を文章で説明する
  - EMF/WMF等、Readツールで開けない・文字列抽出もできない画像の場合は、無理に内容を捏造しない。該当箇所に「元のExcelファイルの図を参照」という趣旨の注記を残し、どの節のどんな図が省略されたか分かるようにする
- 図の対応方針に幅がある場合（省略するか・簡略化して再現するか等）は、最初の1件が見つかった時点でユーザーに確認し、以降は同じ方針を貫く

### 7. Markdownの執筆

以下を守りながら、手順3〜6で読み取った内容をMarkdownとして書き出す。

- 見出し番号の階層をMarkdownの見出しレベル（`#`〜`####`程度）に対応させる。それより深い番号（`(1)`など）は太字の小見出しや箇条書きで表現する
- セクション番号・タイトル・本文の文言は原文のまま転記する。原文に誤り（番号の重複など）があっても、それを「直さず」そのまま転記する（本スキルは翻訳・要約ではなく構造変換が目的のため）
- 折り返しで複数物理行に分かれていた文章は、1つの段落・1つの表セルとして結合する
- 表はMarkdownテーブル（`| ... | ... |`）で表現する
- URLやログ出力フォーマットのような固定書式の文字列は、コードブロック（\`\`\`）で囲む
- 図はMermaidコードブロック（\`\`\`mermaid）として埋め込む。フローチャートは`flowchart`、時系列のやり取りは`sequenceDiagram`を使う
- 元のシートに存在しない説明文・要約・補足を新たに書き加えない（見出しの構造化やMermaid化そのものは変換行為として許容されるが、原文にない「解説」を追加しない）

### 8. 検証

書き上げたMarkdownについて、以下を確認する。

- 見出し番号（例: `5.1`〜`5.23`）が抜けなく連番で揃っているか（`grep -n "^## "` などで確認）
- コードブロックのフェンス(\`\`\`)の数が偶数か（開き忘れ・閉じ忘れがないか）
- grid出力の最終行（本文の末尾）まで転記が反映されているか（末尾が長い文章の場合、複数物理行にまたがる続きを読み落としやすいので特に注意する）

### 9. ユーザーへの報告

変換完了時に、以下を簡潔に報告する。

- 変換対象にした可視シート、除外した非表示シート（あれば理由も）
- Mermaid化した図の数、および省略した図があればその節番号と理由

## 補足: `scripts/inspect_xlsx.py` について

xlsxを展開したディレクトリ（`xl/`を含む）を第1引数に、以下のサブコマンドを渡して使う。

| サブコマンド | 用途 |
|---|---|
| `sheets` | シート名・可視状態・対応する描画パートの一覧 |
| `grid <シート> [--all]` | シート全体を行番号付きでダンプ（既定では空行省略） |
| `cells <シート> <開始行> <終了行>` | 指定範囲のセルとマージ情報を詳細表示 |
| `shapes <シート>` | 図形・テキストボックス・画像のテキストと位置を一覧表示 |

シートは名前（例: `"5.API処理方式"`）またはインデックス（0始まり）のどちらでも指定できる。
